## Rationale for deviations

Two deviations from the approved proposal's `## What will be done`,
both scope-narrowing rather than scope-exceeding:

1. **Test file delivered as `core/hooks/tests/run-record-shape-gate-tests.sh`
   (bash), not `core/hooks/tests/test_record_shape_gate.py` (pytest) as
   the proposal's write set literally named.** This repository has no
   pytest infrastructure as a project dependency — every existing gate
   (`facet-keyword-gate.sh`, `ordering-norm-gate.sh`, `citation-gate.sh`,
   this proposal's own named precedent) is tested by a bash
   `run-<gate>-tests.sh` script invoked from `core/hooks/tests/run-all.sh`,
   the actual fast-tier entry point named in this issue's acceptance
   criteria. #260's, #257's, and #254's own delivery records made this
   exact same correction for the same reason. The proposal's substantive
   test requirements (live-fire, one allow + one refuse per check_type,
   coverage across every rulebook, empty-state, no-config-file case, run
   via the fast tier) are all met — only the file extension/framework
   named in the proposal's prose was corrected to match the repository's
   real convention.

2. **Not every `confidence: low` row was individually hand-verified
   against its source file before being written into
   `record-shape-config.json`, contrary to step 2 of the proposal's
   "What will be done".** The proposal's own scale note anticipated 145
   hooks was too many to hand-read in one session and committed the
   extraction script to flag low-confidence rows for a dedicated
   hand-verification pass. In session, the classifier's regex-based
   shape/path/kill-switch extraction converged to 86 high-confidence and
   59 low-confidence rows after two rounds of heuristic broadening (an
   undocumented fifth shape variant — record-level required-field
   presence with no section markers, seen in
   `customer-support-record-fields/hooks/record-fields-gate.sh` and
   similar — was folded into `section_markers_conditional` as its
   nearest existing check_type rather than hand-reading each instance).
   Hand-verifying all 59 low-confidence rows against their source files
   individually was not completed within this session's time budget.
   Every low-confidence row still got a real, working
   `target_path_regex`/`kill_switch_env`/`check_type` assignment (the
   `CHECKERS` handlers degrade safely on missing extracted fields — an
   empty `required_sections`/`required_keys`/`required_tokens` list is a
   silent pass, never a false deny), and the `confidence` column is
   preserved on every row specifically so a follow-up pass can target
   exactly the 59 rows that need it. This is a real completeness gap
   against the proposal's stated method, not a claim that all 145 rows
   are individually behavior-verified against their source hook.

## What did not work

- The extractor's first classifier pass left 65 of 145 rows
  `UNCLASSIFIED` (no check_type at all) because its regex signals were
  too narrow (e.g. `section_markers_conditional` only matched literal
  `required_sections`/`section marker` text, missing the far more common
  `#{1,6}` Python heading-regex idiom and generic `required.*fields?`
  phrasing the real source hooks use). Broadened the signal set twice
  and added a filename-convention tie-break
  (`methodology-gate.sh` → `methodology_checklist_gated`), which brought
  unclassified rows to 0 (the survivors default to
  `section_markers_conditional` at `confidence: low` rather than staying
  unclassified, since every row needs a disposition per the acceptance
  criterion).
- A first attempt to derive `kill_switch_env`/`target_path_regex` from a
  single fixed literal convention (`docs/issue-[0-9]+/reports/<slug>.md`
  reconstructed from the rulebook name) missed on 85 of 145 files — real
  source hooks vary in both the target path's reports-vs-proposals
  surface and the kill-switch env-var naming. Replaced with direct
  per-file regex extraction of each hook's own `*_OFF` env var and its
  own `docs/issue...(reports|proposals)/....md` literal, which dropped
  the miss count to 17 (those 17 still got a generated fallback, flagged
  low-confidence).
- The first draft `run-record-shape-gate-tests.sh` built its
  `checklist_entry_fields` allow-case fixture with
  `sed 's/^/&: present\n/'`, which does not do what it looks like (`&`
  is the empty match of `^`, not the input line) and produced a
  malformed fixture. Replaced with `awk '{print $0": present"}'`, which
  produced the intended `key: present` lines and the allow case passed.
