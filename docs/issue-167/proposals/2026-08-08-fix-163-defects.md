## Request
Fix the 3 confirmed-reproduced silent-failure defects from #163: scope-gate
auto-approves arbitrary Bash during an approved proposal (Critical),
hunt-guard's agent-type check misses the real namespaced dispatch name
(High), and trailer-gate's commit-verb regex is bypassed by a quote-split
`git commi""t` (High).

## Constraints
- Fixes must be mechanical/pattern-based, matching each file's existing
  fail-closed style — no new dependency, no new env var.
- The three named repro tests in `tests/test_silent_failure_repros.py`
  (A2/A4/A5) must flip from demonstrating the bug to demonstrating the fix,
  and the existing "control" assertions in the same tests must keep passing.
- No regression in `core/hooks/tests/run-gate-lib-tests.sh` or
  `run-role-gates-tests.sh`.

## Rationale
For A4, considered widening the withhold regex list to also catch variable
indirection (e.g. detect any bare `$VAR` before a withheld verb) — rejected
because regex-based command analysis is exactly the mechanism the issue
says to stop trusting ("Bash commands are never checked against the frozen
write set at all"); patching the regex only shrinks the bypass surface, it
doesn't close it, and a future indirection form (`eval`, command
substitution, aliasing) would reopen it. Instead, Bash stops being
auto-approved by default: the gate only vouches (permissionDecision: allow)
for a narrow allowlist of commands it can prove are read-only/inspection
(git status/diff/log, ls, cat, python3 -m pytest, etc. — same posture as
"decline to vouch, let the normal prompt decide" already used for
`withheld()` matches), and defers to the normal permission prompt for
everything else, including anything referencing paths outside the frozen
write set. This keeps today's "gate declines, prompt decides" fallback
behavior (never a hard denial of a legitimate build command) while removing
the blanket allow.

For A2, considered normalizing by stripping any `plugin:` prefix before
comparing — rejected because that would also accept an attacker-chosen
`evil:warrant-hunter`, which is not a hunter this repo defines. Instead
match a fixed known-name set/pattern: bare `warrant-hunter` or exactly
`warrant:warrant-hunter` (the one namespaced form this plugin actually
registers, per `warrant/agents/warrant-hunter.md`).

For A5, considered adding more literal-string quote-split variants to the
regex (`commi""t`, `com""mit`, etc.) — rejected as whack-a-mole against
infinite quote placements. Instead, reuse the file's own established
resolve-then-match precedent (`_extract_resolvable_expr`, added for
issue-141 to resolve `-m` payloads by shell effect, not raw text): strip
adjacent-empty-quote pairs (`""` / `''`) from the command before running
the `git ... commit` regex, so the match runs against the same string the
shell would actually execute.

## What will be done
- `warrant/hooks/scope-gate.sh`: replace the Bash branch's default-allow
  with a narrow read-only allowlist match; anything not on it exits without
  emitting `permissionDecision: allow` (falls through to the normal prompt,
  same as a `withheld()` match today).
- `warrant/hooks/hunt-guard.sh`: change the `agent_type != "warrant-hunter"`
  check to match either `warrant-hunter` or `warrant:warrant-hunter`.
- `core/hooks/trailer-gate.sh`: before running `commit_m = re.search(...)`,
  build a quote-collapsed copy of `command` (strip `""`/`''` pairs) and
  match the git-commit regex against that copy instead of the raw string.
- `tests/test_silent_failure_repros.py`: update the three tests' assertions
  (A2 bypass case now denied/capped, A4 indirected-rm and unrelated-curl
  cases now not auto-allowed, A5 quote-split case now denied) so each test
  demonstrates the fix, keeping the existing control assertions.

## Out of scope
- A7 (gh-guard renamed-binary gap) — issue #167 explicitly excludes it
  (tracked, accepted gap per its own test).
- Any other hardening beyond the three named defects (e.g. broader Bash
  static analysis, sandboxing).

## How you'll know it worked
- `python3 -m pytest tests/test_silent_failure_repros.py -k "A2 or A4 or A5"`
  green with fixed-behavior assertions.
- `bash core/hooks/tests/run-gate-lib-tests.sh` and
  `bash core/hooks/tests/run-role-gates-tests.sh` green (no regression).
