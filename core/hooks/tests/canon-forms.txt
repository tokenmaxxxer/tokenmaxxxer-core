# Registered directive.sh combination shapes (issue-78). One entry per
# line: name:pattern-description, mirroring canon-manifest.txt's plain-line
# convention. stub-check.sh classifies each non-blank/non-comment/
# non-assignment line of a directive.sh against the union of these shapes;
# a line matching any registered pattern is not "regrown boilerplate".
#
# single-call: the original shape — the only non-blank/non-comment/
# non-assignment line is the one core_role_directive call.
single-call:^[[:space:]]*core_role_directive[[:space:]]
#
# fragment-loop: sales-rulebook's approved (issue-10) directive-fragment
# combination — a bash array of fragment names, a `for frag in ...; do`
# loop iterating it, and the loop's `done` terminator, in addition to the
# core_role_directive call itself.
fragment-loop:^[[:space:]]*[A-Za-z_][A-Za-z0-9_]*=\(
fragment-loop:^[[:space:]]*for[[:space:]]+[A-Za-z_][A-Za-z0-9_]*[[:space:]]+in[[:space:]]+
fragment-loop:^[[:space:]]*done[[:space:]]*$
#
# fragment-loop body rows (issue-83): sales-rulebook's real (not toy)
# fragment-loop directive.sh spreads its `for ... in` argument list across
# backslash-continued lines instead of one array literal, puts `do` on its
# own line, and its loop body is a test-and-source row
# (`[ -f "$frag" ] && . "$frag" 2>/dev/null`), not a bare `core_role_directive`
# call — none of which the original header/footer-only patterns above cover.
fragment-loop:^[[:space:]]*"[^"]+"[[:space:]]*\\?[[:space:]]*$
fragment-loop:^[[:space:]]*do[[:space:]]*$
fragment-loop:^[[:space:]]*\[[[:space:]]+-f[[:space:]]+"\$[A-Za-z_][A-Za-z0-9_]*"[[:space:]]+\][[:space:]]+&&[[:space:]]+\.[[:space:]]+"\$[A-Za-z_][A-Za-z0-9_]*"([[:space:]]+2>/dev/null)?[[:space:]]*$
#
# unregistered-stub (issue-175): architecture-rulebook's real-repo shape —
# a plain second directive.sh line beyond the core_role_directive call,
# calling a single named helper function with no arguments (its own stub-
# combination convention, distinct from fragment-loop's array/for-loop
# shape). Constructed from the issue's own gap description
# ("unregistered stub shape") — no access to the real repo's literal
# bytes; stated assumption, not hidden (docs/issue-175/proposals/
# 2026-08-08-canon-duplication-full-manifest-and-stub-shapes.md).
unregistered-stub:^[[:space:]]*[A-Za-z_][A-Za-z0-9_]*_directive_extra[[:space:]]*$
#
# layered-directive (issue-175): accessibility-rulebook's real-repo shape —
# "no layered-directive allowlist" per the issue: a second, layered source
# line pulling in a sibling directive fragment ahead of the
# core_role_directive call, rather than sales-rulebook's array/for-loop
# combination. Constructed from the issue's gap description; same stated-
# assumption basis as unregistered-stub above.
layered-directive:^[[:space:]]*\.[[:space:]]+"[^"]*layered-directive\.sh"([[:space:]]+2>/dev/null)?[[:space:]]*$
